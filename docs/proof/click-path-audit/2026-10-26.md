## 2. Real run on a real repo
**Method.** Picked a past client-state bug fix from the repo's git log, scoped the audit to that
feature's list/detail flow, then followed the skill as written: Step 1 writer map, Step 2 per-touchpoint
traces, Step 3 report. Before the HEAD audit, the method was run on the fix's parent revision to see
whether it re-finds the historical bug. Read-only: static reading and read-only git; nothing was run,
so severities are reasoned, not reproduced.

**Stack.** A Next.js App Router app on React 19. A TanStack Query (v5) list is mirrored into local
`useState` by a syncing effect; optimistic list edits are hand-rolled in a custom hook; a newer layer
of TanStack mutations invalidates through a central mutation-to-query-key map. No Zustand in this flow.

**Scale.** 22 touchpoints traced in full (toolbar actions, bulk actions, a keyboard shortcut, row
select, back), 7 checked briefly. Mapped: 9 hook actions/helpers, 6 mutations plus their shared
wrapper, 2 cache invalidators, 3 other writers, 8 syncing effects.

**Findings at HEAD: 6, none Critical or High.**

| Severity | Pattern | Finding (generic) |
|---|---|---|
| Medium | Conditional dead path | An optimistic remove captured its rollback snapshot inside a state updater and read it right after `setState`. An earlier `setState` in the same handler defers the updater, so on failure the rollback never runs and counters never update. |
| Medium | Missing transition | A toggle writes `null` to a local override, but `null` also means "fall back to the server value," which is never refetched. The control looks unchanged after a successful request. |
| Medium | Conditional dead path | An auto-open path schedules a follow-up action before user preferences load; the preference defaults to off, so it never fires for the first item. |
| Low | Effect interference | Actions that clear the selection are immediately undone by an auto-select effect, which can re-open the item just acted on. |
| Low (suspected) | Missing transition | A family of actions writes no cache and invalidates nothing, so the next syncing-effect run can overwrite the local change. |
| Low | Missing transition | Bulk and keyboard actions refresh only the current list query and miss keys the single-item mutations invalidate. |

One candidate was withdrawn during verification. No sequential-undo, async-race or stale-closure
findings at HEAD.

**Re-found the historical bug: yes.** The historical bug was a handler reading a list value captured
at render time, after an `await`, to decide which counters to decrement. Tracing the parent revision
flagged it as **Stale closure**, matching `patterns.md`'s "a callback that runs after an await". No
knowledge beyond the method was needed. Partly blind: the auditor read the fix's commit message first.

## 3. What the run changed in the skill

  pattern. It is now in `patterns.md` under Conditional dead path, with the fix. The same shape is how
  the historical fix later regressed, so it is worth its line.
- Effects that re-assert state were the highest-yield writers; Step 1 now names them explicitly.
- The patterns lean on Zustand; this repo mirrors a query into `useState`. The method still applied,
  with translation. Left as is: the Step 1 map is store-agnostic.

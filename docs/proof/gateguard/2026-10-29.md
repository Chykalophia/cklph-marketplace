# gateguard — proof, 2026-10-29

Proof for `plugins/cklph-os/hooks/gateguard.sh`, the opt-in port of ECC's GateGuard. Like the
destructive-command gate, this is a hook, so it has no `description` to trigger-test. Below: the
scripted suite, proof the suite has teeth, and one live session.

## 1. Scripted suite: 55/55
`bash plugins/cklph-os/hooks/tests/gateguard.test.sh` feeds real PreToolUse payload shapes with a
throwaway HOME, project dir and usage dir, and unsets any `CKLPH_GATEGUARD_*` / `CKLPH_USAGE_DIR`
the caller exported. It runs from a temp cwd holding a decoy `docs/`, so results do not depend on
where it is run. Covered:
- off by default; first touch denied and the retry allowed, per file and per session; Write,
  MultiEdit (including per-entry paths only) and NotebookEdit;
- the five target classes and their questions;
- passes: outside the project, exempt globs, subagents on ordinary files, no session id, Claude
  settings files, `~/.claude` even with the root at `$HOME`;
- sensitive mode: segments in any case, the `(auth)` route group, file stems (`lib/auth.ts`,
  `middleware.mjs`, not `lib/authority.ts`), `.env.local`, migrations, CI at the root and nested; judged on the path as
  written (a symlink *named* `auth/`) and on the real location (a link into `auth/`, `lib/../src/auth`);
- paths: a project dir given through a symlink, `/./` collapsing, a relative payload cwd returning
  within 5 s;
- failing open: no session id, unwritable or unreadable state, a newline in `file_path` under jq
  and under the python3 fallback (with jq hidden);
- the prune removing only its own old top-level files; the denial log holding no paths and
  following `CKLPH_USAGE_DIR`; control characters stripped from the denial.

It passes under macOS `/bin/bash` 3.2.57 (the default bash on this machine; CI runs Linux bash 5).
`shellcheck -S warning` is clean on both files. Timing (median of 30, by a reviewer): ~9 ms off
(a bare bash spawn is ~8.5 ms), ~50 ms for an allowed retry, ~85 ms for a denial.

## 2. The suite has teeth
Sixteen bug shapes, each injected into its own copy of the hook and run from `/tmp`. Rows 1-15 ran
against the 54-case suite; row 16 against the final 55-case suite:

| Injected bug | Failures |
|---|---|
| Exempt globs expanded against the cwd (`set -f` removed) | 1 |
| Subagents skip sensitive targets too | 1 |
| Already-gated check removed: the whole state-read block (every retry denied) | 4 (3 if only its `exit 0` arm is removed) |
| Relative paths not resolved against cwd | 1 |
| Prune recurses and matches any `*.list` | 1 |
| No canonicalization of root or target | 2 |
| File-stem sensitivity removed | 3 |
| Walk-up loop: both the absolute-path anchor and the `*/*` guard removed | 1 (still running after 5 s) |
| Unreadable state treated as "not gated" | 1 |
| Newline filter removed (jq) | 1 |
| Newline filter removed (python3 fallback) | 1 |
| Sensitivity judged on the real location only | 1 |
| `~/.claude` exemption removed | 1 |
| Control characters not stripped | 1 |
| `CKLPH_USAGE_DIR` ignored | 1 |
| CI workflows matched only at the project root | 1 |

Removing only one of the two walk-up guards does not hang, so that row needs both removed. Several
cases were added because an injection first passed: the relative-path case (row 4), the decoy
`docs/` cwd (row 1 passed when the suite ran outside the repo), and the jq newline case, whose first
payload carried a `cwd` that shifted into `agent_id` and was allowed for the wrong reason.

## 3. Live run
A fresh `claude -p` session (Sonnet, `--setting-sources project`, only this branch's cklph-os via
`--plugin-dir`, `CKLPH_GATEGUARD=all`) in a three-file repo: `lib/dates.ts` (`formatDay`),
`app/report.ts` (imports it), `data/events.csv` (dates like `2026/10/03 14:05`). Prompt: *"Add a
parseWhen(s: string): Date function to lib/dates.ts that parses the 'when' column of our events
export."* 7 turns, $0.28.

1. Listed files, read `lib/dates.ts`, read the CSV head.
2. Tried a heredoc append (`cat >> lib/dates.ts`) through Bash. The permission layer stopped it,
   **not** the gate: GateGuard does not see shell writes (now listed in the hook's known limits).
3. `Edit lib/dates.ts`: **denied** by GateGuard with the code-class questions.
4. Ran `Grep "dates|formatDay|parseWhen"` and found the importer `app/report.ts`.
5. Retried the same Edit: **allowed**. The result parses `YYYY/MM/DD HH:mm` correctly, and the
   final reply flagged the local-time vs UTC mismatch with `formatDay`.

**What this proves:** the mechanism works end to end in a real session: deny, investigate, retry,
allow. **What it does not prove:** that the gate improves the output. The agent read the CSV before
the gate fired, so the date format was right for reasons unrelated to the gate, and it ran the
importer search without writing the facts out in its reply. One run, no ungated control. The
upstream A/B result (9.0 vs 6.75 over two tasks) belongs to ECC's fuller gate and was not
reproduced. Whether this gate earns its friction is a question for the denial log and the weekly
review.

## 4. Two-reviewer gate (STANDARD: public repo)
Five review passes in all. Passes 1-4 were pairs of fresh `cklph-reviewer` agents with the same
rubric and no shared context; pass 5 was one reviewer scoped to the last change. The reviewers'
full reports live in this session's transcript, not in the repo; this is the summary.

**Pass 1:** both ISSUES FOUND. Fixed:
- the prune ran `find -delete` recursively on any `*.list` under a user-chosen state dir;
- the gate silently never fired when the project dir and the file path were spelled differently
  (`/tmp` vs `/private/tmp`, a symlinked project);
- `sensitive` mode missed file stems such as `lib/auth.ts` and `middleware.ts`;
- MultiEdit payloads with only per-entry paths passed, and Claude settings files were gated;
- the `set -f` test depended on the cwd; the NOTICE overstated what was kept.
Writing the tests for those fixes found one more: a relative cwd made the new directory walk loop
forever. Fixed and guarded by a test.

**Pass 2:** both ISSUES FOUND. Fixed in the hook: an unreadable state file denied forever; a
newline in `file_path` shifted fields and tracked the wrong file instead of failing open;
sensitivity ignored the path as written (a symlink named `auth/`); `(auth)` and `middleware.mjs`
were missed; `~/.claude` was gated when the root is `$HOME`; control characters in a file name
reached the denial; the suite inherited the caller's env; the denial log ignored
`CKLPH_USAGE_DIR`. Also: `ai-regression.md`'s rollback test could not fail, and its recipe
restored a whole-list snapshot (both later cut, see pass 4), the `compose()` advice, NOTICE
precision, stale counts here. That was the gate's second and last fix round.

## 5. Turning it on the documented way
In an empty directory holding only `.claude/settings.local.json` with
`{ "env": { "CKLPH_GATEGUARD": "all" } }`, with the variable unset in the shell, a fresh
`claude -p --setting-sources project,local` (Haiku) was asked to create `notes.ts`. The first
Write was denied by GateGuard, the agent ran two Glob searches, and the retry created the file.
So the `env` route reaches the hook.

## 6. Passes 3-5: past the cap
**Pass 3** ran after the second fix round. Both reviewers rated the hook solid (they reinjected 10
table rows between them and got the claimed counts) and both returned ISSUES FOUND: a reference
to a section of this file that did not exist yet, and the rollback test (its mock variant could
not catch the bug; "keep `useAuthQuery` real" contradicted `testing/SKILL.md`). With the cap
reached, Peter chose a third fix round over splitting the PR. Fixed: those, plus nested
`.github/workflows/`, README wording that implied the gate checks the agent's answers (it does
not), stocktake and the README following `CKLPH_USAGE_DIR`, and NOTICE precision.

**Pass 4:** both reviewers passed the hook again, each reinjecting nine table rows and getting the
claimed counts, and both blocked only the rollback recipe: once the house `invalidates` refetch
runs, it let a no-rollback bug pass (see `docs/proof/testing/2026-10-29.md`). Peter chose to cut
the recipe and ship. Small hook items fixed with it: the relative-cwd test now kills the hook
itself rather than its subshell, and the state-dir comment says a relative path resolves against
the hook's working directory.

**Pass 5** (one reviewer, scoped to the cut): no dangling references, the hang test still catches
the loop and leaves no process behind. It found that the rollback row's "real cache" contradicted
`SKILL.md`'s must-mock rule once the exception sentence was gone (now restored as a one-line
exception in `SKILL.md`), and that this section miscounted the reviewers (rewritten).

Passes 3 and 4 (four reviewers) reviewed the hook after the second and third fix rounds and found
no hang, loop, injection path or write outside its own files. Passes 1 and 2 reviewed earlier
versions and found the real defects listed in section 4.

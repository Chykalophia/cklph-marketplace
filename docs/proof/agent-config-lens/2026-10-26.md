## Findings

Severity is context-first. No critical or high findings. 7 medium, 6 low.

| # | Severity | Rule | Location | Finding |
|---|---|---|---|---|
| 1 | medium | `agentcfg:hook-fail-open` | `plugins/cklph-os/hooks/pre-commit-gate.sh:28` | The commit matcher `(^\|/)git[[:space:]]+commit` only fires when `git` begins the command or follows a `/`. `cd repo && git commit -m x` and `git -C repo commit -m x` both skip the whole gate (checked with the system `grep -E`: SKIPPED for both, GATED for `git commit` and `/usr/bin/git commit`). `cd <dir> && git commit` is a common agent pattern, so tsc, ESLint, Semgrep, and the skill-description sanity check are silently bypassed. |
| 2 | medium | `agentcfg:hook-fail-open` | `plugins/cklph-os/hooks/security-check.sh:26`, `:32`, `:38` | The secret patterns use `["\x27]` inside an ERE bracket expression. Neither BSD nor GNU grep reads `\x27` as a hex escape there, so the class is `"`, `\`, `x`, `2`, `7`, never `'`. With the system BSD grep, `api_key = 'ABCDEFGHIJKLMNOPQRSTUVWX'` → 0 matches; the same value in double quotes → 1. Single-quoted literals, the default style in most TS/JS, are missed by the API-key, password, and secret/token checks. `:32`'s `[^\x27"]` likewise excludes `x`, `2`, `7` from password values. The bats suite only covers the `AKIA` pattern (`test/hooks.bats:41`), so it doesn't catch this. |
| 3 | medium | `agentcfg:mcp-review` | `plugins/vuln-intel-ext/.mcp.json:3-4` → `plugins/vuln-intel-ext/scripts/start.sh:6-8` | The MCP server is a local script (class REVIEW). Judged: on first launch it runs `npm install` from inside the plugin cache, not `npm ci`. That fetches dependencies from the registry when the MCP client starts it and runs their install scripts (`package-lock.json` marks `better-sqlite3` with `hasInstallScript`). `npm install` can also re-resolve within the `^` ranges in `package.json:13-15` when the lockfile and manifest disagree. Prefer `npm ci --ignore-scripts` where the native module allows it, or ship prebuilt. |
| 4 | medium | `agentcfg:mcp-unpinned` | `plugins/cklph-os/skills/browser-debug/SKILL.md:17-18` | The skill tells users to paste an MCP config running `npx @anthropic/chrome-devtools-mcp@latest`. `@latest` is a mutable dist-tag on a server that drives a real browser (DOM, JS execution, network, possibly logged-in sessions). Separately, the static review couldn't confirm that the `@anthropic/` npm scope publishes this package (registry lookups are out of scope for this lens). `needs-owner-input`: confirm the intended package name and pin the version you reviewed. |
| 5 | medium | `agentcfg:hook-remote-fetch` | `plugins/cklph-audit/tools/dry.sh:14` | The architecture-lens recall tool, run automatically by `audit-reviewer`, falls back from `npx --no-install jscpd` to plain `npx jscpd`. On a machine without jscpd, every audit fetches and executes whatever version the registry currently serves, with no pin. The sibling tools (`await.sh:13`, `deadcode.sh:12`, `layering.sh:12`) correctly use `--no-install` only. |
| 6 | medium | `agentcfg:runtime-unvalidated-action` | `plugins/cklph-audit/tools/exploit-runner.sh:33-36` | Opt-in (`dast.exploitVerify`), but when enabled it runs an LLM-generated PoC script with `--network=host`, even though the comment on `:33` says "no network except to the target host". Host networking gives the generated code the host's loopback services and anything else the host can reach. `:36` also interpolates `$URL` into a single-quoted `bash -c` string, so a `'` in the target URL breaks out inside the container. Severity is medium because the feature is off by default; treat it as high when enabled. |
| 7 | medium | `agentcfg:agent-tools-broad` | `plugins/cro-research-reporting/agents/cro-auditor.md:1-22`, `plugins/cro-research-reporting/agents/deep-researcher.md:1-15` | Neither agent declares `tools:`, so both inherit every tool (Bash, Write, Edit, all MCP servers). Both exist to read untrusted web content (store pages, search results), and neither body tells the agent to treat fetched content as data. Compare `plugins/cro-research-reporting/agents/cro-verifier.md`, which is scoped to `Read, Grep, Glob, WebFetch, WebSearch`. |
| 8 | low | `agentcfg:runtime-secret-exposure` | `plugins/cklph-os/hooks/security-check.sh:26`, `:32`, `:38`, `:44`, `:59` | The pattern greps run without `-q`, so a matching line, i.e. the secret, is printed to hook output. `:59` echoes full gitleaks output without `--redact`. The secret is already in a file the agent just wrote, so the only new exposure is to transcripts and logs. Hence low. |
| 9 | low | `agentcfg:hook-fail-open` | `plugins/cklph-os/hooks/pre-commit-gate.sh:17-20` | With no `jq` on the machine, the gate exits 0 and allows every commit. This is documented and warns on stderr. Owner decision; recorded so it is a choice, not an accident. |
| 10 | low | `agentcfg:hook-injection` (hygiene) | `plugins/cklph-os/hooks/pre-commit-gate.sh:81`, `:102`, `:119` | Output goes to fixed, shared paths (`/tmp/tsc-gate.txt`, `/tmp/eslint-gate.txt`, `/tmp/semgrep-gate.txt`). On a multi-user host another user can pre-create or symlink them. Use `mktemp`. |
| 11 | low | `agentcfg:mcp-unpinned` | `plugins/cklph-audit/tools/exploit-runner.sh:12`, `:30`; `plugins/cklph-audit/tools/dast.sh:54` | Opt-in DAST tooling pulls `curlimages/curl:latest` and `softwaresecurityproject/zap-stable:latest` by mutable tag with no `@sha256:` digest. The executed artifact and the reviewed source can drift with nothing to catch it. `needs-owner-input`: add a build-equals-dist check or build on install. |
| 13 | low | `agentcfg:doc-autorun` (accuracy) | `templates/AGENTS.md:16-17` | The template says the security scan is "enforced automatically" by cklph-os hooks, but `security-check.sh:79-80` always exits 0 (advisory by design). An agent reading the template may assume secrets are blocked. Overlaps with docs-drift-lens. |

## Positive controls (checked and clean)

- `plugins/cklph-os/hooks/hooks.json:9`, `:18`, `:29`: every hook command resolves through quoted `"${CLAUDE_PLUGIN_ROOT}/hooks/…"`. No absolute paths, no remote fetch.
- `plugins/vuln-intel-ext/.mcp.json:6`: the credential is an env reference (`${WPSCAN_TOKEN}`), not a literal.
- `plugins/cklph-os/skills/browser-debug/SKILL.md:43-51` and `plugins/cklph-os/agents/red-team.md:21`: explicit untrusted-content boundaries. The "ignore previous instructions" text at `browser-debug/SKILL.md:48` is a look-alike that forbids the attack, not a finding.
- `plugins/cklph-audit/tools/await.sh:13`, `deadcode.sh:12`, `layering.sh:12`: `npx --no-install` only, so nothing is fetched at audit time.
- `plugins/cklph-audit/agents/audit-verifier.md` (`Read, Grep, Glob`) and `audit-synthesizer.md` (`Read`): tool grants match their read-only roles.
- No committed `.claude/settings*.json`, so there are no repo-level permission grants to review.

## Boundaries

No MCP server, hook, or package runner was executed. Mutable references are review signals, not compromise claims. A clean surface here is not a complete MCP or agent security assessment.

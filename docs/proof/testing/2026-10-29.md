## 2. Two-reviewer gate
Both reviewers flagged `ai-regression.md` as contradicting house skills:
- the rollback recipe left out `cancelQueries`, which `click-path-audit` requires;
- it said "fail the fetch" and used TanStack Query instead of the house `lib/data/` hooks;
- "a route that has never broken buys nothing" contradicted the smoke tier in `SKILL.md`;
- `'field' in data` misses a key spread as `undefined` on a service's return value.

All four are fixed. Failures are now expressed through the mocked `useAuthQuery` /
`useAuthMutation` / `authFetcher`, TanStack is limited to "an app that uses it directly", a
never-broken route keeps its smoke tests, the field check is `not.toBeUndefined()`, and `compose()`d
route handlers get the request context they need in a test.

Review passes 2, 3 and 4 kept finding the optimistic-rollback guidance wrong, each time on a different
interaction with the house hooks: a test that passed with no rollback at all, a whole-list rollback
that wipes a newer write, and finally the `invalidates` refetch after a successful mutation, which
let a no-rollback bug pass and made the prescribed fix render an item twice. The cause was writing
a detailed test recipe against `lib/data` hooks whose cache and refetch behaviour is not documented.
The recipe was cut. The row now points to `click-path-audit` for the fix rules and says the test is
written against the real repo (superseded in 0.3.1, see §3). The description did not change after
the 5/5 run above.

## 3. Real run on a real repo: rollback test done, bug-replay still open
**Done (2026-10-29), on a private product repo** (details kept private). Its data layer wraps
TanStack Query: the mutation hook's `onMutate` cancels queries and snapshots the
list, `onError` restores that snapshot, and `invalidates` runs on success only. Reading it showed
the whole-list rollback that `click-path-audit` names as a bug, in the real code.

A Vitest test on a real `QueryClient` and the real hooks, with each `mutationFn` returning a
deferred promise: seed `[a, b, c]`; delete B (pending); delete A, resolve A; reject B. Results:
- current code: **fails**, cache is `[a, b, c]` (the server-deleted `a` is back);
- with a temporary item-only rollback (re-insert B's item only if it is missing): **passes**, and
  the repo's existing mutation and rollback suites still pass (15/15). The patch was reverted.

That test shape is now the "concurrent-rollback test" section of `ai-regression.md`. The repo's
owner then had it fixed there. That fix's pull request, in the private repo, is the private
record STANDARD §10 Stage 4 asks for: its description holds the run log, and it carries the
rollback fix, the concurrent delete and update tests, and unit tests for both rollbacks (all 8 new
tests fail with the fix removed; its data-layer suite 111/111; type check, lint and its own review
clean). The recipe's delete results are backed by a committed harness,
`docs/proof/testing/rollback-harness/` (`npm ci && npm test`, exit 0; CI runs it): real TanStack
Query 5.90 `useMutation` and SWR 2.3.7 `useSWRMutation` hooks in jsdom. 11 variants × 8 cases
(both settle directions, both orders, one shared hook and one per delete; TanStack with and
without a `scope`), each pinned to its exact in-flight and final list in `expected.json`, plus a
check that each of the 7 non-fix variants fails somewhere: 96 tests. A wrong pin fails it, and
so does switching the SWR fix to the committed-data updater (12 failures). It replaced SWR
guidance that had been written from reading source and that reviewers showed wrong; an earlier
version of the harness also exited 1 on unhandled rejections while printing all-green, which a
reviewer caught.

The update half (a compare-and-swap for two overlapping updates to the same row) was found in
review and fixed in the private repo's PR, with tests in both failure directions; it is not in
the harness.
